#889 - Integrate CORA Document Review
What & Why
Turn the existing source-document, records, and CORA citation capabilities into one production workflow based on the approved mockups. Attorneys should be able to open a cited CHRONDEX document from CORA or the records view, keep the case context visible on desktop, and read the same document in a focused CORA-centered mobile state without losing their session or case context.

Done looks like
Desktop attorneys can open a case document from Records or a CORA citation and see the case rail/context, readable document viewer, and CORA conversation together.
Mobile attorneys can open a cited document from CORA into a full-screen readable state, inspect page text or the source image, navigate back to CORA, and keep the active case/session intact.
Document review deep links preserve the selected case, active document, and page when appropriate, and browser back/forward behaves predictably.
Page citations resolve to the correct tenant-owned document and page; missing, expired, unauthorized, or unindexed content shows a clear recoverable state rather than a blank viewer.
Existing CORA voice/text behavior, records processing, upload flow, and source-access security continue to work.
Desktop and mobile layouts are verified at representative viewport sizes, with no horizontal overflow or blocked controls.
Out of scope
A redesign of unrelated dashboard modules, exports, billing, intake, or litigation-analysis screens.
Reprocessing, reindexing, regenerating, or modifying the authoritative Sharkey corpus.
Changing document storage, tenant authorization policy, or the CORA model pipeline unless required to support the review state.
Replacing the existing mockup sandbox components with production code verbatim.
Steps
Map the shared review state -- Define the production navigation/state contract for active case, document, page, and return destination so Records, CORA citations, timeline links, and browser history converge on one review flow.
Complete the desktop review surface -- Add the approved three-region experience to the dashboard, reusing the existing case context, indexed page content, source image controls, and CORA rail without unmounting or interrupting an active CORA session.
Complete the mobile review surface -- Make cited documents open as a focused, readable mobile state with page text/image access, clear return-to-CORA behavior, safe scrolling, and responsive controls.
Connect all entry points -- Wire record rows, timeline/source links, and CORA document-read chips to the shared review flow; preserve the selected case and return to the originating view after close.
Harden states and access behavior -- Handle loading, empty, missing-page, expired-source, unauthorized, and legacy-document cases with explicit UI states while preserving the existing server-side ownership and discovery-password checks.
Validate interaction and responsive behavior -- Add or update focused tests for navigation and document access, run type checks and the relevant test suite, restart the application workflow, and inspect desktop/mobile previews for visual regressions.
